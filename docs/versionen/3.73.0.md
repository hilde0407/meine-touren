**Ehrlich vorweg:** Geprüft mit neuen Server-Tests (`tests/test_wanderfuehrer_zip_373.py`); **nicht am Handy und nicht im Browser mit einer echten ZIP-Datei**.

## Befund
Die Seite „Wanderführer“ (Verwaltung) nahm nur einzelne GPX-Dateien an (`accept=".gpx"`); ZIP-Dateien gab es dort gar nicht.

## Neu
* Verwaltung → Wanderführer: „GPX- oder ZIP-Dateien auswählen …“. Eine ZIP-Datei wird auf dem Server gelesen (`POST /api/guides/zip`): alle GPX-Dateien darin werden Buchtouren (Titel aus der GPX-Datei, `__MACOSX` und versteckte Dateien zählen nicht).
* Buchname: das Feld „Buch“; ist es leer, der Dateiname ohne „.zip“.
* Titelbild: Liegt ein Bild (JPG, PNG, WebP) in der ZIP, wird es das Titelbild des Buchs – nur wenn das Buch noch keins hat. Mehrere Bilder: Namen mit „titel“, „cover“ oder „bild“ zuerst, dann am wenigsten tief, dann alphabetisch. Das Bild wird wie beim eigenen Titelbild neu kodiert und verkleinert.
* Eine Tour mit gleichem Titel im selben Buch wird nicht doppelt angelegt („schon vorhanden“).
* Grenzen (Schutz vor ZIP-Bomben): ZIP höchstens 60 MB, 1000 Einträge, entpackt 400 MB, je GPX 20 MB.
* Kaputte Dateien in der ZIP stoppen den Import nicht; sie erscheinen als „fehlgeschlagen“.
